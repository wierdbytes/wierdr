# Сессия сабагента Claude Code по тапу

Вопрос: тап по строке сабагента Claude Code в Wierdr открывает терминал родителя. Можно ли
показывать сессию самого сабагента, как у сабагента pi (у того свой терминал herdr-core)?

**Ответ.** У обычного сабагента (инструмент Agent без команды) отдельной сессии нет: это
цикл внутри процесса Claude, вынести его некуда. Тиммейта (agent teams) можно сделать
отдельным процессом Claude в своём терминале hc: Claude сам так умеет в режиме
`teammateMode: "tmux"`, а tmux можно подменить шимом, который переводит его команды в `hc`.
Это способ ниже, «Тиммейты в своих терминалах через tmux». Пока не сделано, записано на
будущее. Проверенные альтернативы — в конце.

Всё проверено 2026‑11‑18 на Claude Code 2.1.319 (как у пользователя) и 2.1.327, с
`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` в `~/.claude/settings.json`. Внутренности бэкенда
tmux прочитаны из строк бинарника 2.1.319 (`strings "$(readlink -f /opt/homebrew/bin/claude)"`):
он не документирован и может поменяться с любым обновлением.

## Тиммейты в своих терминалах через tmux

### Как Claude запускает тиммейтов в панелях

Настройка `teammateMode` (`auto` | `tmux` | `iterm2` | `in-process`; флаг запуска
`--teammate-mode`) выбирает, где живут тиммейты. В `tmux` и `iterm2` каждый тиммейт —
отдельный процесс `claude --agent-id … --agent-name … --team-name … --agent-color …
--parent-session-id … --agent-type … --model … --permission-mode …` в своей панели; с лидом
он общается файлами‑почтовыми ящиками команды, не через панель. В `$.agent.list()` лида
такой тиммейт есть, но «runs no loop here: its id is its address» (`name@team`), а статус
`running` / `idle` берётся из реестра команды.

Бэкенд tmux (класс с `type="tmux"`) зовёт программу `tmux` из `PATH` (константа `"tmux"`, без
пути) и пользуется немногим:

| Шаг | Команда tmux | Что отвечает tmux |
|---|---|---|
| Есть ли tmux | `tmux -V` | код 0 |
| Своя панель лида (внутри tmux) | `$TMUX_PANE`, иначе `display-message -p '#{pane_id}'` | `%3` |
| Окно лида | `display-message [-t <pane>] -p '#{window_id}'` | `@1` |
| Сколько панелей | `list-panes -t <window> -F '#{pane_id}'` | id по строке |
| Новая панель (внутри tmux) | `split-window -d -t <pane> -h -l 70% -P -F '#{pane_id}' -- cat` (дальше `-v`/`-h` по очереди) | id новой панели |
| Новая панель (вне tmux) | `has-session -t claude-swarm`; `new-session -d -s claude-swarm -n swarm-view -P -F '#{pane_id}' -- cat`; `list-windows -t claude-swarm -F '#{window_name}'`; `new-window …`; `split-window … -- cat` — на своём сервере `-L claude-swarm-<pid лида>` | id панели |
| Оформление | `set-option -p -t <pane> window-style / pane-border-style / pane-active-border-style …`, `select-pane -t <pane> -T <имя тиммейта>`, `set-option -p … pane-border-format …`, `set-option -w … pane-border-status top`, `select-layout … main-vertical / tiled`, `resize-pane -t <pane> -x 30%` | код 0 |
| Запуск тиммейта | `set-option -p -t <pane> remain-on-exit failed`; `respawn-pane -k -t <pane> -- '<команда одной строкой>'` | код 0 |
| Конец | `kill-pane -t <pane>` (и `kill-session` при уборке) | код 0 |

Панель создаётся с заглушкой `cat`, а сам тиммейт стартует `respawn-pane` командой‑строкой
(на Linux перед ней приписан перенос в cgroup: `sh -c '{ echo $PPID > …/cgroup.procs; }' sh …; <команда>`).
Имя тиммейта приходит раньше команды (`select-pane -T`). Есть ещё переменная
`CLAUDE_CODE_TEAMMATE_COMMAND` (судя по имени, подменяет команду запуска тиммейта; не
проверено).

### Шим

Скрипт `tmux` в плагине `cc` (например `Integrations/claude-code/bin/tmux`), первым в `PATH`
процесса Claude. Каждый вызов — отдельный процесс, поэтому соответствие «панель → терминал
hc» он держит в файле состояния на лида (`$TMPDIR/wierdr-cc-tmux-<pid Claude>.json`).

| Команда | Шим |
|---|---|
| `-V` | `tmux 3.4 (wierdr hc shim)`, код 0 |
| `split-window` / `new-session` / `new-window … -P -F '#{pane_id}' -- cat` | завести панель `%N` без процесса, напечатать `%N` |
| `display-message -p '#{pane_id}'` / `'#{window_id}'` | `%0` (лид) / `@0` |
| `list-panes -F '#{pane_id}'`, `list-windows -F '#{window_name}'`, `has-session` | из файла состояния |
| `select-pane -t %N -T <имя>` | запомнить имя |
| `respawn-pane -k -t %N -- '<команда>'` | `hc run --bg --name <имя> --cwd <cwd> -- sh -c '<команда>'`, запомнить адрес терминала |
| `kill-pane -t %N` | `hc kill <адрес>` |
| `kill-session` | `hc kill` всех своих |
| остальное (`set-option`, `select-layout`, `resize-pane`, `switch-client`…) | код 0, ничего |

`hc run` из процесса Claude наследует `HC_TERMINAL_ID` лида, поэтому терминал тиммейта —
ребёнок терминала лида (поле `parent`; `--die-with-parent`, чтобы не пережил лида). Дальше
ничего нового не нужно: в терминале тиммейта работает свой Claude со своим плагином `cc`
(свои `agent.*`, свой статус 7501), и Wierdr показывает его как обычного сабагента с
терминалом (`SubAgentIndex`): своя строка с моделью и контекстом, тап — его живая сессия,
в которую можно писать; Keep делает её вкладкой. Десктоп herdr увидит те же терминалы.

### Как включить

- `teammateMode: "tmux"`: флагом `--teammate-mode tmux` при запуске Claude в herdr (шаблон
  hc или алиас) или настройкой. Настройка глобальная — действует и вне herdr, где шима нет
  (там Claude найдёт настоящий tmux или не запустит тиммейта в панели).
- Шим в `PATH`: плагин может сам — `$.env.set("PATH", "<папка шима>:" + PATH)` в
  `session.start`, только внутри терминала herdr-core (`HC_TERMINAL_ID`). По документации
  `$.env.set` меняет окружение «this process and everything it starts after»; доходит ли это
  до запуска `tmux` самим Claude, не проверено.
- Внутри или вне tmux: что проверяет «внутри» (скорее всего `$TMUX`), не выяснено. Ставить
  `TMUX` в терминале herdr опасно: Claude считает терминал tmux и может заворачивать свои
  escape‑последовательности (картинки, уведомления, возможно OSC 7501) в passthrough tmux,
  которого herdr-core не понимает. Ветка «вне tmux» (`claude-swarm`, свой сервер `-L`)
  обходится без `TMUX`, шиму её и обслуживать.

### Что учесть в Wierdr и плагине

- Двойные строки: лид продолжит перечислять такого тиммейта в `$.agent.list()` (id
  `name@team`), и плагин запишет его в `agent.subagents_meta`; у Wierdr будет и строка
  терминала, и строка из метки. Плагину — пропускать тиммейтов с id вида `name@team` (или
  Wierdr — записи, чей `name` совпадает с именем терминала‑ребёнка).
- Только тиммейты: у обычных сабагентов (Agent без команды, Explore и т. п.) режима панелей
  нет, их строки остаются строками из метки.
- Риски: недокументированный интерфейс (имена команд, форматы `-F`, порядок вызовов),
  глобальная настройка, процесс Claude на каждого тиммейта (память, свой кэш промпта).

### Проверить первым делом

1. Шим, который только пишет каждый вызов в лог и отвечает правдоподобно; Claude с
   `--teammate-mode tmux` и шимом в `PATH`; запустить тиммейта — увидеть точную
   последовательность вызовов и строку команды в `respawn-pane`.
2. Тот же шим с `hc run`: тиммейт отвечает лиду, `SendMessage` доходит, `shutdown`
   завершает процесс (терминал заканчивается), `kill-pane` при уборке команды.
3. `$.env.set("PATH", …)` из плагина вместо `PATH` при запуске.

## Проверенные альтернативы

### Вид самого Claude: `$.ui.view`

TUI Claude умеет показывать транскрипт агента вместо основного («Viewing @helper · esc to
return»), и промпт тогда пишет этому агенту («Message @helper…»). Плагин может переключить
вид вызовом `$.ui.view({ agentId })` (`{}` — назад к основному), но только «в ответ на ввод
самого человека»:

- из команды плагина (`$.command.register` + хук `command.run`), набранной в промпте, —
  работает в обоих видах; команда пишется в основной транскрипт строкой `❯ /<команда>` и
  её видит модель (спросил — перечислила);
- из `prompt.submit` основного вида — работает; отказ `{ drop: '' }` не оставляет следа
  ни в транскрипте, ни у модели, но отказанный текст остаётся в поле — его надо вернуть
  `$.prompt.fill`;
- из `prompt.edit` (вставка) — отказ: `{ deny: "not person-initiated" }`; зато хук видит
  вставку (`inputText`) до того, как она попала в черновик, и может её не пустить;
- в виде тиммейта всё отправленное уходит тиммейту, `prompt.submit` лида не вызывается;
- переключение самим человеком (список агентов, Esc) хук `ui.view` не вызывает; узнать
  текущий вид можно только из `e.props.view` в хуке отрисовки полосы над промптом
  (`AbovePrompt`).

Рабочая схема: Wierdr вставляет в терминал метку `⟦wierdr:view <id>⟧` и Enter; `prompt.edit`
меняет метку на команду плагина и запоминает черновик; команда переключает вид и возвращает
черновик (он едет в поле нового вида: поле у Claude одно). Проверено с черновиком в обе
стороны. Минусы: строки команды в основном транскрипте и контексте модели, отдельный
механизм знать текущий вид.

### Своё окно Wierdr

Транскрипт каждого сабагента и тиммейта Claude хранит в
`~/.claude/projects/<папка проекта>/<сессия>/subagents/agent-<id>.jsonl` (рядом
`agent-<id>.meta.json`); `<сессия>` — `agent.session` лида. Wierdr мог бы читать его
(`file.read`) и рисовать сам, как окно сабагента pi без панели: в терминал Claude ничего не
пишется, но только чтение, и нужен свой рендер сообщений и вызовов инструментов.
