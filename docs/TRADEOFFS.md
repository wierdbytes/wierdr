# Wierdr — допущения, компромиссы и ближайшие планы

## Допущения

1. **Mac доступен по SSH.** Remote Login включён (на этом Mac уже включён; sshd предлагает
   `publickey,password,keyboard-interactive`). iPad видит Mac в одной сети
   (`mentoair.local` / `192.168.x.y`) или через Tailscale (`mentoair-1` / `100.x.y.z`;
   iPad `ipad165` и iPhone `iphone-13-pro-max` уже в tailnet). Вне дома iPhone ходит к Mac
   только через Tailscale.
2. **herdr-core на Mac** установлен (`~/.local/bin/hc`, 0.1.20). Протокол — generation 1;
   проверено с hc 0.1.20 и удалённой машиной `lf` (0.1.14) через релей ядра Mac.
3. **Десктоп Herdr может работать одновременно** — Wierdr рассчитан именно на это: общий
   документ `herdr-app` правится только compare‑and‑swap’ом с валидацией (см. ниже).
4. **Тема**: тёмная — Atom One Dark, светлая — Paper (как в `wierd-layout`); переключается
   системной темой iPad или вручную в Settings. Цвета спейсов берутся из `shared.json`
   десктопа; если его нет — по тому же правилу палитры. Статус done — зелёный темы
   (`#98c379` / `#1a7f37`, её ANSI green), а не синий, как в Herdr; марка blocked — красная
   точка, как у done, а не плашка «!»; working — жёлтая точка, а не спиннер; так же в
   Live Activity.
5. **iPad Pro 13" M4** зарегистрирован в команде разработчика `AUL4CCB2XY`
   (его UDID есть в профиле), поэтому сборку можно ставить сразу.
   **iPhone 13 Pro Max** (iOS 27.2.1,
   Developer Mode включён) — тоже в профиле команды. Минимальная версия — iOS/iPadOS 18.

## Компромиссы (осознанные)

| Тема | Решение | Почему / цена |
|---|---|---|
| Эмулятор терминала | **SwiftTerm** (MIT), Metal‑рендер | У Apple нет терминального API. Десктоп использует libghostty‑vt; его сборка под iOS (Zig) — отдельный проект. SwiftTerm зрелый, но кодирование некоторых клавиш (kitty keyboard, modifyOtherKeys) и отрисовка могут чуть отличаться от Ghostty. |
| UI‑шрифт | **Geist** (как в оригинале) в сайдбаре и панели, **JetBrains Mono** — модель, effort, возраст, папки (как в строках десктопа), на iPhone тоже; SF — в системных экранах (формы, алерты, настройки, меню), в поле сообщения и поле Go to | Максимальная похожесть на десктоп там, где ты его видишь каждый день; нативность — в остальном. |
| Иконки | SVG Herdr (Lucide/LobeHub/Simple Icons) в asset catalog, а не SF Symbols | Совпадение с оригиналом 1:1. SF Symbols — только в свайпах и системных меню. |
| Размер терминала | Wierdr — **активный зритель**: при показе/вводе терминал принимает размер панели iPad (как второе окно десктопа) | Так работает herdr-core: размер задаёт последний активный зритель. Если Mac и iPad смотрят на один терминал одновременно, он «перетягивается»: Mac заберёт размер при клике/вводе. Режим «только смотреть» (`observe` + масштабирование) — в планах. |
| Подключённые терминалы | Терминалы аттачатся при показе; невидимые > 60 с отключаются, максимум 12 одновременно | Экономия батареи/трафика на мобильном. Возврат к табу = мгновенный переаттач с перерисовкой (2000 строк истории). Десктоп держит все табы подключёнными. |
| Картинки (Kitty graphics) | Хранилище картинок эмулятора — 320 МБ на экран (как у Ghostty), а не 10 МБ по умолчанию в SwiftTerm | С 10 МБ скриншоты pi (до 2000 px, до 16 МБ в RGBA каждый) не показывались или вытесняли друг друга, и при прокрутке pi на их месте оставалось пусто. **Ограничение:** перерисовка herdr-core при аттаче передаёт только текст, без картинок. Если картинка пришла, пока терминал не был подключён (фон, таб скрыт > 60 с, реконнект, смена шрифта), её нет, а pi выставляет её повторно только по id (`a=p`), так что до перезапуска pi на её месте пусто. Заново pi отправляет картинку только при изменении числа колонок. Правильное исправление — в core: класть картинки в перерисовку. |
| Фон / блокировка | При уходе в фон iOS замораживает сокет; при возвращении — пинг и быстрый реконнект | Что происходит с агентами, пока приложение в фоне, показывает Live Activity (iPhone), её шлёт Mac — см. строку ниже. Обычных уведомлений нет. |
| Live Activity агентов | Её стартует, обновляет и закрывает `wierdr-push` на Mac через APNs: push‑to‑start на токен устройства (токен приложение кладёт в документ `wierdr-push` ядра), обновления и конец — broadcast на канал (iOS 18), у каждой активности свой. Сервера нет: «сервер» — сам Mac. Подробно: [live-activity.md](live-activity.md) | Приложение в фоне не может держать SSH, а Live Activity сама в сеть не ходит; остаются только пуши. Канал вместо токена каждой активности: иначе приложению пришлось бы в фоне, разбуженным после push‑to‑start, подключаться по SSH, чтобы сообщить токен. **Цена:** нужен APNs‑ключ `.p8` и галка Broadcast у App ID; Mac должен не спать (иначе через 25 мин «Not updated»); только iPhone; демон — на том компьютере, к которому подключается телефон. Смахнутая активность возвращается, когда откроешь Wierdr (он сообщает, что её нет), иначе — только со следующим стартом. Каждый start по пушу обязан нести alert (без него ActivityKit активность не создаёт), а alert вибрирует: поэтому в простое активность держится ещё 2 ч, показывая «idle», и запуск агента за это время — обычное обновление. |
| SSH | Только Ed25519/ECDSA‑P256 ключи и пароль | SwiftNIO SSH не поддерживает RSA‑ключи пользователя, keyboard‑interactive, ssh‑agent, ProxyJump. Для Mac это не мешает (ключ генерируется на iPad). |
| Known hosts | Своё хранилище TOFU (JSON в Application Support), не `~/.ssh/known_hosts` | На iOS нет общего known_hosts. |
| Адопция «сиротских» терминалов | Не реализована (сознательно, ради сохранности общего документа) | Терминалы с метками `herdr.space` без панели подхватывает десктоп. Если Wierdr запустил терминал, а запись документа не удалась, его подхватит десктоп при следующем запуске. |
| Удаление мёртвых панелей | Wierdr убирает панель, если её терминал завершился (`exited`/`killed`) — с задержкой 3 с, чтобы обычно это успевал сделать десктоп | Это единственная «самостоятельная» запись в документ. Отключается `EngineOptions.allowWrites = false`. |
| Мод‑панели десктопа (Files/Changes/Memory, markdown‑viewer) | Показываются как строка «panel» в сайдбаре, в сетке — заглушка | Это JS‑моды GPUI, на iPad их не исполнить. |
| Сессии pi (кнопка «history») | Не перенесено | В оригинале — `node sessions.mjs` на Mac; это отдельная фича (см. планы). |
| Перетаскивание спейсов | Drag и drop UIKit, не SwiftUI: `UIDragInteraction` и меню заголовков — свой `UIContextMenuInteraction` (`SpaceHeaderMenu`) — на одном вью, `UIScrollView` списка, там же `UIDropInteraction` (`SpaceListInteractions`); координаты — окна (сам список перевёрнут); drag начинается, только если касание пришло на заголовок карточки (где оно пришло, помнит свой распознаватель, `TouchCounter`; где заголовки и карточки — пустые UIKit‑вью за ними, `SpaceMarker`). Не своё «удержал 220 мс — карточка поднялась», как на десктопе. Поднятую карточку рисует список (`LiftedCard`), превью системы невидимо; слот и расступающиеся карточки — тоже свои: карточка остаётся в списке пустой (пунктир), порядок до подтверждения документом — свой (до 2 с); у верхнего и нижнего края (под шапкой) список прокручивает display link, ведущий карточку; он же каждый кадр заново выбирает слот, но только по списку в покое (каждая карточка лане ровно под соседней, через `gap`): пока карточки расступаются, SwiftUI двигает их вью покадрово, и посреди анимации слот, только что переехавший, мерился бы как принадлежащий старому месту — с серединой карточки у середины соседней он прыгал туда‑обратно. Цена: следующее решение — после анимации (0,16 с) | Пальцем удержание — это ещё и меню спейса, а система разводит «меню» и «повёл — потащил», только когда drag и меню — взаимодействия одного вью и превью меню — targeted preview, а не свой контроллер: меню SwiftUI с `preview:` (нужно из‑за переворота списка, см. «Список») drag из меню не начинает. Поэтому меню заголовка — своё, UIKit, с картинкой заголовка (`SpaceHeaderBar` через `ImageRenderer`), поставленной в перевёрнутый список с обратным переворотом (проверено в симуляторе iOS 27: меню, потом drag за пальцем). `.onDrag` SwiftUI не годится: когда тащат из открытого меню, он берёт предмет у вью под пальцем, а не у поднятого заголовка. Своё превью — потому что системное ставит себя куда хочет (после меню — по центру под пальцем) и на лету не меняется: снимок, а не вид. Карточка — слой окна, её ведёт сама сессия drag (`location`, каждый кадр), поэтому летает и над панелью; за пределами списка слот стоит на её прежнем месте. Отпущенную за пределами списка карточку ловит прозрачный вид поверх окна (на время drag, сквозной над списком): это для системы drop, слышный сразу, — иначе drag кончается только после её анимации отмены. **Цена:** меню заголовка — UIKit‑меню, собранное руками (пункты не из SwiftUI; для VoiceOver — действия заголовка Rename, New Terminal Tab, Close Space). Если дождаться меню и вести в его сторону, палец сначала идёт по пунктам — отпустишь на пункте, он сработает (в симуляторе drag после выхода за меню не начался — проверить на устройстве). Ворктри не переезжают вместе со своим репо (десктоп сам вернёт их под него). |
| Перетаскивание табов | Пилюлю — на другую пилюлю (`tab.move`), без расступания | Время. |
| Демо‑режим | Команды в демо только показывают тост | Нет фейкового бэкенда. |
| iPhone | Своя раскладка (`App/Sources/Phone`): сайдбар (тот же, что на iPad) — первый экран, и одна панель на экран поверх него; на iPhone в любой ориентации и в узком окне iPad | Широкий iPad — со сплитами, сайдбар рядом с панелью. Подробности и цена — в разделах «Сайдбар» и «iPhone» ниже. |

## Сайдбар: один на iPad и iPhone

| Тема | Решение | Почему / цена |
|---|---|---|
| Один сайдбар | Одна реализация (`App/Sources/Sidebar`) для колонки iPad, оверлея и первого экрана iPhone: карточки спейсов сайдбара iPad (сворачивание, перетаскивание в списке, git и статусы в свёрнутом виде) со строками, порядком снизу вверх, шапкой внизу и кольцами лимитов списка iPhone (решение 16.11, ветка `unified-sidebar`) | Лучшее из обоих в одном коде, одна мышечная память на обоих устройствах. Ушли: на iPad — brand bar, панель лимитов полосками (её части рисуют поповер колец), футер Settings, скобки сплит‑табов, порядок по срочности, кнопка булавки при наведении; на iPhone — табы спейсов, листание страниц, Reorder Tabs, лента «All». Шапка — одна строка: кольца лимитов слева, кольцо статусов посередине, одна кнопка + справа, её меню — новый спейс, Settings и на iPad Hide Sidebar (решение 16.11: настройки и + — одна кнопка, + под правым пальцем). Цена: на iPad строки крупнее и порядок снизу вверх против десктопа (§ «Список под одну руку»); Settings и скрытие сайдбара — на тап дальше (в меню); в узком сайдбаре от колец лимитов остаётся по одному на аккаунт (`SidebarHeaderRow`: кольцу статусов место первым, кольца лимитов берут самую широкую форму, что влезает рядом). |
| Статусы в шапке | Одно кольцо (`StatusRing`, 31,5 pt): чёрточка на агента от 12 часов по часовой, срочные первыми (нужен ты, готово, работает) их цветом, idle — бледные, как дорожка; больше 24 агентов — дуга на статус, не меньше десятой части кольца; внутри — число самого срочного его цветом. Тап — первый агент самого срочного статуса, долгое нажатие — меню со всеми статусами (самый срочный внизу, у пальца). Было: круглые бейджи с числом на каждый статус, залитые его цветом (решение 16.11) | Бейджи занимали 126 pt при многих агентах и были одинаково громкими: залитые «работает» и idle звучали как «нужен ты», а на iPad в 300 pt лимитам оставалось два голых кольца. Одно кольцо по долям не годится — один ждущий тонет в десятке idle. Чёрточка на агента (как у кольца сторис), idle как фон: одна красная чёрточка среди серых видна сразу, 1–4 чёрточки считаются без счёта; число внутри — сколько ждут. Крупнее колец лимитов, пунктиром и с цветным числом — чтобы не читалось как ещё один лимит. Цена: числа остальных статусов — только в меню (VoiceOver читает все); у тапа одна цель вместо четырёх. Сравнивали (макеты 16.11): тихие счётчики (точка + число), бейджи только у «нужен ты»/«готово», кольцо‑компас из четвертей, кольца Activity по штукам (в 36 pt внутреннее — точки), точка на агента, бейдж самого срочного. |
| Список | Перевёрнутый `ScrollView` + ленивый стек, как списки чатов (и Telegram): сам скролл перевёрнут, каждый элемент перевёрнут обратно, так что начало содержимого — низ экрана. Карточка — один элемент стека (заголовок и строки в одном `VStack` на поверхности карточки), а не `List` с карточкой из строк, как было на iPad | Список, нарисованный снизу вверх, стоит у нижнего края сам — это его начало, — и любое изменение (карточка свернулась или развернулась, пришёл агент, раскрылось дерево сабагентов) держит на месте то, что под ним, и двигает только то, что над ним, в той же анимации: карточка разворачивается вверх, сворачивается вниз в свой заголовок, заголовок стоит. С `defaultScrollAnchor(.bottom)` (было) скролл поправлялся отдельно от анимации: заголовок уезжал к верху карточки и возвращался, рывками. `List` у нижнего края не стоит вовсе. Цена: картинка контекстного меню SwiftUI у вью в перевёрнутом списке выходит линией — строки рисуют своё превью заново (`contextMenu(preview:)`), а у заголовка меню своё, UIKit (см. «Перетаскивание спейсов»); drag и drop — свои на `UIScrollView` (у `List` были делегаты collection view, с автопрокруткой у краёв); карточка с десятками строк строится целиком, лениво — только по карточкам. |

## iPhone: компромиссы

| Тема | Решение | Почему / цена |
|---|---|---|
| Сплиты | На iPhone всегда одна панель на экран; панели спейса — полоса чипов под заголовком | Два терминала рядом на 428 pt — по ~28 колонок, нечитаемо. Структура табов/сплитов не меняется (десктоп видит всё как было); Split в меню создаёт панель так же, как на десктопе. |
| Размер терминала | Как на iPad: iPhone — активный зритель. Открыл агента на телефоне — его терминал (и на Mac) становится ~57 колонок | Режим наблюдателя на телефоне нечитаем: 120 колонок в 428 pt — это шрифт ~5 pt. Mac забирает размер по клику/вводу. Пока ты в списке, экрана панели нет: её терминал ничего не меняет и через минуту отключается (вернулся раньше — вывод уже на месте). |
| Шрифт и отступы | 12 pt и 8 × 6 pt на iPhone (14 pt и 14 × 12 — на iPad) | ~57 колонок в портрете, ~120 в альбомной; щипком 9…24 pt. Отдельная настройка на каждом устройстве. |
| Клавиатура и терминал | Пока открыта клавиатура (поле сообщения или прямой ввод), терминал становится ниже (RESIZE), а не уезжает под неё | Видно последний вывод агента, пока пишешь ответ; цена — TUI перерисовывается при каждом показе/скрытии клавиатуры. |
| Поле сообщения всегда под терминалом | Как композер Telegram: скрепка, поле, кнопка отправки внутри поля с первым символом; тап — клавиатура, двойной тап по терминалу — убрать её, поле сужается до двух строк. Пока клавиатура у самого терминала (двойной тап), поля нет | Сообщение — в один тап, черновик всегда виден (до двух строк, прокручивается). Цена: терминал ниже на ~76 pt всегда (на iPad — на высоту поля под панелями), и TUI перерисовывается, когда поле растёт или сужается (RESIZE на каждую новую строку). Раньше поле открывалось свайпом + Type и под терминалом ничего не было. |
| Compose | Текст уходит одной вставкой (bracketed paste, если программа его включила), Return — отдельной записью через 60 мс | Многострочное сообщение не отправляется построчно, автодополнения TUI (`/`, `@`) не перехватывают ввод. Длинную вставку агент может свернуть в «[Pasted text …]» (как при Ctrl+V). |
| Картинки | `terminal.put` кладёт файл рядом с терминалом, в поле вставляется путь; картинка уходит агенту путём в тексте | Так делает и десктоп (Ctrl+V картинки). Агент читает файл своим инструментом; превью в самом TUI нет. HEIC → JPEG, > 2048 px уменьшается (лимит core — 8 МБ). Камеры нет (нужен отдельный запрос доступа) — только фотоплёнка и буфер. |
| Смарт‑пунктуация | Поле — свой `UITextView`: «умные» кавычки выключены всегда, тире — только для агентов; оставшееся (кавычки из длинного нажатия, `—flag`) → `"` `'` `--` при отправке | Для шелла автокоррекция и заглавные выключены, для агентов — включены. ## Ближайшие планы

1. **Режим наблюдателя** для терминалов, которые сейчас открыты на Mac: `observe: true` +
   `resize_notifications` + масштабирование шрифта под ширину; активный режим — по тапу/вводу.
   Тогда iPad не будет менять размер терминалов на Mac, пока ты просто смотришь.
2. **Уведомления**: баннеры «агент ждёт тебя / закончил» внутри приложения есть на iPhone
   (на iPad — тоже стоит), дальше — фоновые (BGAppRefresh / свой релей / APNs).

   камера.

   `sessions.mjs`, просмотр/возобновление `pi --session`.
5. ~~Peek сабагентов и «Keep as tab»~~ — есть (дерево сабагентов, окно на iPad, экран на
   iPhone, Keep). Нет «Send back» (вернуть оставленного сабагента под родителя без панели).
6. **Drag & drop** панелей (порядок спейсов и табов уже тащится).
7. **Панель лимитов** (`limits`) — по запросу.
8. **iPhone**: проверить на устройстве; свайп между панелями спейса по терминалу; виджет/Live
   Activity со счётчиками агентов; Share Extension «отправить агенту».
9. Поддержка `~/.ssh/config`‑подобных записей и Tailscale‑дискавери машин.
