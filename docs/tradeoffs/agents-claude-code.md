# Компромиссы: Claude Code

## Claude Code: данные агента

**Решение:** Модель, effort, контекст, кэш, лимиты и сабагенты Claude Code пишет мод Claude Code из
этого репозитория (плагин `cc@wierdr`, `Integrations/claude-code`, [claude-code.md](../claude-code.md))
в те же метки `agent.*`, что pi-wierdr (`agent.app = claude-code`, `agent.pid` — pid Claude, он же
foreground терминала), и в документ `limits`; Wierdr читает их тем же кодом, что у pi
(`AgentLabels.meta`: effort `low…max`, `cache_ttl` 3 600 000 мс, провайдер `anthropic`). Статус
Claude сообщает сам (OSC 7501)

**Почему / цена:** Не хуки настроек и не status line: мод работает внутри процесса Claude и получает
модель, effort, контекст, кэш, лимиты и сабагентов напрямую; хуки видят только события (модель и
контекст — из транскрипта, лимитов нет), а status line у Claude одна — наша заменила бы твою.
**Цена:** без плагина у Claude Code в строке — имя программы, без кольца; мод привязан к его API
модов (обновления Claude могут его ломать — правится в одном месте).

## Claude Code: заголовок строки

**Решение:** У агента с 7501 `app = claude-code`: пока он ждёт тебя или упал (blocked/error) и есть
`msg` — `msg` (вопрос, разрешение, ошибка); иначе говорящий заголовок терминала (название сессии —
придуманное им или `/rename`, спиннер срезан), потом `msg`, потом обычные запасные. У pi и всех
остальных — как было: `msg` первым. Одно правило (`AgentText.title`) — в строке, капсуле экрана
панели, панели агентов, баннере, Live Activity, «from …» окна сабагента; строки сабагентов («чем
занят») остаются `msg`‑первыми

**Почему / цена:** У pi `msg` — постоянное имя сессии, у Claude — мимолётная деталь (прогресс, «1
shell still running», итог хода), и строка прыгала бы между ними; его постоянное имя — заголовок
окна. Вопрос важнее имени, когда он ждёт тебя. Различаем по `app`, а не по программе: правило — про
то, как Claude заполняет 7501. **Цена:** пока Claude не дал сессии имя, заголовок окна — «Claude
Code» (не говорящий), и видна деталь из `msg`.

## Claude Code: фоновая работа

**Решение:** Записи 7501 (`records`, по id: фоновые сабагенты и шеллы Claude, пока идут) — строки
дерева агента (`TaskRecord`, `RecordKid`, `SidebarRow.tree`), под терминалом, который о них
сообщает, после его детей‑терминалов, по id; без терминала: тап — его терминал, ни свайпов, ни меню,
ни окна; сабагент — две строки, как сабагент pi (ниже), шелл — одна, как терминал. Счёт: бот =
сабагенты с терминалом + у каждого терминала блока `max(agent.subagents, записи‑сабагенты)`; `>_` =
терминалы + фоновые шеллы (id Claude `b` + 8 знаков base36). В кольцо статусов, бейджи карточек,
Live Activity и срочность агента записи не идут

**Почему / цена:** Дерево — уже место для «чем занят агент кроме себя»; последними — потому что
приходят и уходят с каждой фоновой задачей, и строки терминалов того же уровня не скачут. `max`, а
не сумма: `agent.subagents` плагина и записи — одна и та же работа, а записей нет у обычных (не
фоновых) сабагентов, так что ни одно число не полнее другого всегда. Срочность и счётчики — у самого
агента: его статус 7501 уже говорит, что он работает или ждёт. **Цена:** шелл от сабагента отличаем
по форме id Claude (другая форма — считается сабагентом); заблокированная фоновая задача не делает
агента красным (только бейдж бота краснеет), если Claude не сообщил blocked сам.

## Claude Code: строка сабагента

**Решение:** Как у сабагента pi (`PhoneRecordRowContent` по образцу `PhoneKidRowContent`, 50 pt):
точка, заголовок, возраст; модель, `@effort`, кольцо. Строки — по метке плагина
`agent.subagents_meta` на терминале Claude: JSON по id из `$.agent.list()` на каждого живого
сабагента и тиммейта (`pending`/`running`/`waiting`/`idle`: `title`, `name`, `status`, `since`,
`model`, `model_id`, `effort`, `ctx`, `ctx_max`, `started`); запись 7501 к строке находится по id (у
сабагента он тот же, проверено вживую), иначе по заголовку (у тиммейта ключ записи — id задачи `t…`,
которого API не даёт; заголовок = `description`), и даёт ей состояние (работает, ждёт тебя) и
вопрос; строка без записи — тиммейт между ходами (idle) или сабагент, ждущий свой шелл (working).
Строка держит id из списка (`StatusRecords.merge`). Доверие — как к самим `agent.*` (правило pid).
Возраст — со смены статуса, которую видел мод (`since`: спавн, первый запрос после простоя, чтение
списка), иначе с запуска. `agent.subagents` считает и простаивающих тиммейтов. Без плагина — только
записи, пока работают, с именем программы на месте модели и без возраста

**Почему / цена:** Запись 7501 — только состояние и заголовок, пишет её сам Claude (плагин в
терминал писать не может и перетёр бы её), и есть она только пока агент работает: три простаивающих
тиммейта живой сессии не были видны совсем; другого канала из Claude, кроме меток, нет. Одна метка,
а не по метке на сабагента: ключ известен заранее, так что выход и перезапуск мода снимают её
целиком (динамические ключи от упавшего Claude никто бы не убрал), и смена состава — одна запись.
Возраст со смены статуса — как у сабагента pi; для работающего это и есть время с запуска, как его
показывает сам Claude. **Цена:** при каждом запросе любого сабагента метка переписывается целиком
(слитно за 150 мс), а пока есть команда, мод опрашивает список раз в 5 с; два работающих тиммейта с
одним описанием могут получить чужие записи; до 2.1.327 список не даёт окна и старта — окно только
для модели сессии, старт — от `agent.spawn`, после перезагрузки мода на ходу — без возраста, а
статус простаивающего — с момента перезагрузки.
