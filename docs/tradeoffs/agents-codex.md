# Компромиссы: Codex

## Codex: данные агента

**Решение:** Модель, effort, контекст, сессию и число сабагентов Codex пишет плагин Codex из этого
репозитория (`codex@wierdr`, `Integrations/codex`, [codex.md](../codex.md)) — хуки Codex
(`SessionStart`, `UserPromptSubmit`, `PostModelRequest`, `Stop`, …), каждый пишет в сокет herdr-core
те же метки `agent.*`, что pi-wierdr (`agent.app = codex`, `agent.pid` — pid TUI, он же foreground
терминала), и лимиты в документ `limits` (аккаунт `codex.<slug>`); Wierdr читает их тем же кодом,
что у pi и Claude (`AgentLabels.meta`: «GPT-6.1 Sol» под `openai` → «6.1 Sol»; effort Codex
`none…ultra`: `none` — цветом `off`, `ultra` — градиентом `max`). Статус Codex сообщает сам (OSC
7501). Сабагенты Codex идут в его процессе: ни терминалов, ни записей 7501; `agent.subagents` — в
бейдже бота, по каждому работающему плагин пишет и `agent.subagents_meta`

**Почему / цена:** У Codex нет API внутри процесса (как моды Claude Code) — только хуки: команды,
которые он запускает на события сессии и отдаёт им её данные; плагин собирает их вместе, ставится и
снимается целиком ([codex.md](../codex.md)). `ultra` выше `max` — тем же градиентом, а не новым цветом:
лестница кончается на «максимум», и отдельный цвет над красным ничего бы не прибавил. **Цена:** без
плагина у Codex в строке — имя программы, без кольца; хуки видят только события — то, о чём Codex не
сообщает событием, обновляется со следующим.

## Codex: статус

**Решение:** У агента с 7501 `app = codex`: `idle` — idle, что бы ни говорил счётчик ходов; `done` —
done, пока его ход не просмотрен (`turn > herdr.seen`, так что «просмотрено» и Mark Idle работают),
иначе idle; working/blocked/error — как у всех (`StatusRule.status`). У pi, Claude и остальных — как
было: idle с непросмотренным ходом — done. Одно правило в `TerminalInfo.status` — строки, кольцо
статусов, бейджи карточек, панель агентов, баннер, счётчик кнопки «назад», Live Activity
(`wierdr-push` читает тот же `WierdrModel`). Mark Unread у Codex, сказавшего idle, не предлагается и
ничего не пишет

**Почему / цена:** Счётчик `turn` herdr-core у Codex растёт без законченного хода: при запуске
(Codex сообщает working → idle, пока стартуют его MCP‑серверы), на `/new` и на каждом запросе
разрешения, — и свежий Codex горел бы зелёным «закончил», пока не посмотришь. Codex сам шлёт `done`,
когда ход кончился, и `idle` по следующей клавише в своём TUI — ему можно верить. **Цена:** Codex,
которому ответили прямо в его TUI (на Mac), гаснет сразу, не дожидаясь, пока Wierdr его покажет;
десктоп Herdr со своим правилом по‑прежнему может показывать свежий Codex как done.

## Codex: заголовок строки

**Решение:** У агента с 7501 `app = codex` говорящий заголовок — заголовок его окна без частей Codex
(`AgentText.codexTitle`): спиннер срезан (`shownTitle`), спереди — мигающий
`[ ! ] Action Required | ` / `[ . ] Action Required | `, сзади — последняя часть ` | X`, если X —
имя проекта, как его делает Codex (`terminal_title_project_name`: имя папки git‑корня, или папки с
`.codex` проекта, иначе cwd, обрезанное до 24 знаков с «...»), то есть имя cwd терминала или любой
папки, в которой он лежит. Остаётся имя треда (пока его нет — начало промпта, обрезанное Codex до 48
знаков); только проект — пусто. Цепочка — общая: `msg` (у Codex его нет) → имя таба (если назван) →
этот заголовок → «Codex». То же в строках сабагентов (Codex, запущенный другим агентом через
`hc run`). У pi и Claude — без изменений

**Почему / цена:** Имя треда — то, чем Codex называет сессию, и его видно только в заголовке окна;
проект уже сказан карточкой спейса, а «Action Required» — статусом. Проект сверяем с папками cwd, а
не просто режем последнюю часть: заголовок настраивается (`tui.terminal_title`), и чужой последний
элемент (ветка, модель) должен остаться. **Цена:** запущенный с `-C <папка>` Codex (cwd процесса —
не папка проекта) оставит ` | проект` в заголовке; тред, названный как папка над cwd, и одиночный
элемент заголовка с таким именем пропадут (покажется таб или «Codex»).
